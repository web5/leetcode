# 算法通识

---

**Q1：时间复杂度和空间复杂度怎么算？常见量级排序？**

**A：**

- 复杂度描述的是**输入规模 n 增长时资源消耗的增长趋势**，忽略常数与低阶项（大 O 记法）。
- 常见量级：`O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)`
- 快速判断：一层循环 O(n)、嵌套两层 O(n²)、每次减半（`while (n) n/=2`）O(log n)、分治 `T(n)=2T(n/2)+O(n)` → O(n log n)（主定理）。
- **均摊复杂度**：动态数组 push 单次最坏 O(n)，但连续 n 次总代价 O(n) → 均摊 O(1)。
- 空间复杂度：递归要算**调用栈深度**；原地算法 O(1)。

> 实践提醒：当 n 小（< 50）时常数项可能更重要（插入排序在小数组上比快排快）；当 n 极大时，O(n log n) 与 O(n) 的差别决定生死。

**Q2：常见排序算法的对比？**

**A：**

| 算法 | 平均 | 最坏 | 最好 | 空间 | 稳定 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 冒泡 | O(n²) | O(n²) | O(n) | O(1) | ✅ | 基本只用于教学 |
| 选择 | O(n²) | O(n²) | O(n²) | O(1) | ❌ | 交换次数最少 |
| 插入 | O(n²) | O(n²) | O(n) | O(1) | ✅ | 近乎有序时极快；小数组首选 |
| 希尔 | O(n^1.3) | O(n²) | — | O(1) | ❌ | 分组插入 |
| **快排** | O(n log n) | O(n²) | O(n log n) | O(log n) | ❌ | 实际最快，缓存友好 |
| **归并** | O(n log n) | O(n log n) | O(n log n) | O(n) | ✅ | 稳定、可外排序（大文件） |
| **堆排** | O(n log n) | O(n log n) | O(n log n) | O(1) | ❌ | 原地，但缓存不友好 |
| 计数/桶/基数 | O(n + k) | — | — | O(k) | ✅ | 非比较排序，受数据范围限制 |

> 工程真相：语言内置排序几乎都是**混合排序** —— Java `Arrays.sort` 对基本类型用双轴快排、对象用 TimSort（归并 + 插入）；C++ `std::sort` 是 Introsort（快排 + 堆排兜底 + 插入优化）；V8 `Array#sort` 用 TimSort。

**Q3：快排为什么快？怎么避免退化？**

**A：** 快排 = 分区（把小于 pivot 的放左边）+ 递归。快的原因：

1. **原地分区**，不需要额外数组；
2. **顺序扫描**，Cache 命中率高（对比堆排的跳跃访问）；
3. 常数小，内层循环简单。

退化风险与优化：

- 有序数组 + 取首/尾做 pivot → 每次只减 1，退化为 O(n²) 且栈深 O(n)（**栈溢出**）；
- 优化：① **随机取 pivot** 或**三数取中**；② **三路快排**（处理大量重复元素，一次把等于 pivot 的全放中间）；③ 小区间（< 16）切换**插入排序**；④ 递归深度超限时切**堆排**（Introsort）；⑤ 尾递归优化/先递归较小区间，栈深限 O(log n)。

**Q4：什么是排序的稳定性？哪些场景需要？**

**A：** 相等元素在排序后**保持原有相对顺序** = 稳定。

- 稳定：冒泡、插入、归并、计数/桶/基数；
- 不稳定：选择、快排、堆排、希尔。

为什么重要：**多关键字排序**。例如先按"价格"排、再按"销量"排，若第二次排序稳定，则同销量的商品仍按价格有序。实现方式：稳定排序，或把多个关键字合成一个比较器（`a.sales - b.sales || a.price - b.price`）。

**Q5：二分查找的边界怎么写才不出错？**

**A：** 关键是**明确不变式**（区间定义），两种写法二选一，不要混：

```js
// 写法 A：闭区间 [l, r]，循环条件 l <= r，收缩为 r = m - 1
let l = 0, r = n - 1;
while (l <= r) { const m = l + ((r - l) >> 1); if (a[m] < t) l = m + 1; else r = m - 1; }
// 结束时 l 是第一个 >= t 的位置（lower_bound）

// 写法 B：左闭右开 [l, r)，循环条件 l < r，收缩为 r = m
let l = 0, r = n;
while (l < r) { const m = l + ((r - l) >> 1); if (a[m] < t) l = m + 1; else r = m; }
```

要点：

1. 中点写 `l + (r - l) / 2` 防溢出；
2. `m` 的归属要与收缩方式一致，否则死循环；
3. 变体：**lower_bound**（第一个 ≥ t）、**upper_bound**（第一个 > t）、**最后一个 ≤ t = lower_bound(t+1) - 1**；
4. 二分的本质是「**单调性**」，不只用于有序数组 —— 「答案具备单调性」即可二分答案（如"最小速度""最大容量"）。

**Q6：递归的优缺点？怎么优化？**

**A：**

- 优点：代码简洁，天然适合树/图/分治/回溯；
- 缺点：**函数调用开销**（压栈/弹栈）、**栈溢出**风险（深度大时）、可能**重复计算**（斐波那契 O(2ⁿ)）。

优化手段：

1. **记忆化**（`memo`，自顶向下 DP）消除重复计算；
2. **改迭代**（显式栈/队列）避免栈溢出；
3. **尾递归**：部分语言（Scheme、Scala、Kotlin `tailrec`）会优化成循环，**JS/Java/Python 不会**（V8 曾实验性支持 PTC 后移除，故 JS 递归仍会爆栈）；
4. 控制深度：设置深度上限、改 BFS。

**Q7：分治、动态规划、贪心、回溯的区别？**

**A：**

| 方法 | 思想 | 子问题 | 典型题 |
| --- | --- | --- | --- |
| **分治** | 拆成独立子问题，合并结果 | 互不影响 | 归并排序、快排、最近点对 |
| **动态规划** | 拆成**重叠**子问题 + 最优子结构，记录中间结果 | 有重叠，自底向上/记忆化 | 背包、最长子序列、编辑距离 |
| **贪心** | 每步取**局部最优**，不回退 | 需证明贪心选择性质 | 活动选择、Huffman、Dijkstra、跳台阶变体 |
| **回溯** | 穷举所有可能，不行就回退（剪枝） | 全空间搜索 | N 皇后、全排列、组合总和 |

关系：贪心是 DP 的特例（每步只有一个最优选择）；回溯是暴力的 DFS + 剪枝；DP 是"带记忆的搜索"。

**Q8：动态规划的解题步骤？**

**A：**

1. **定义状态**：`dp[i]` 或 `dp[i][j]` 表示什么（最关键）；
2. **推导转移方程**：`dp[i] = f(dp[i-1], dp[i-2], ...)`；
3. **确定 base case**（初始值与越界处理）；
4. **确定遍历顺序**（保证算 `dp[i]` 时依赖的状态已算好）；
5. **空间优化**：滚动数组（只依赖前一行/前几个 → O(1)/O(n)）。

判断能否用 DP 的两个前提：**最优子结构** + **无后效性**（当前状态一旦确定，后续决策不影响它）；重叠子问题只是"值得用 DP"的理由。

> 常见模型：线性 DP、区间 DP（`dp[i][j]` 表示区间）、背包（01/完全/多重）、树形 DP、状态压缩 DP（位掩码）、数位 DP。

**Q9：贪心算法什么时候是对的？**

**A：** 必须满足两条（缺一不可）：

1. **贪心选择性质**：局部最优选择能导致全局最优；
2. **最优子结构**：问题的最优解包含子问题的最优解。

证明手段：**交换论证**（把任意最优解逐步换成贪心解而不变差）、**归纳法**。

反例警示：0-1 背包**不能**用贪心（取价值密度最高的会失败，如容量 10、物品 (6, 30)、(5, 20)、(5, 20) 密度最优解错），必须用 DP；而**分数背包**可以贪心。另如"最少硬币找零"在面额非 canonical（如 11, 5, 1）时贪心也会失败。

**Q10：TopK 问题有哪些解法？**

**A：**

1. **排序**：O(n log n)，简单但慢；
2. **小顶堆（最常用）**：维护容量为 K 的小顶堆，遍历一遍，比堆顶大就替换 → **O(n log K)**，内存 O(K)，适合**海量数据/流式**；
3. **快排分区（quickselect）**：随机选 pivot 分区后只在目标一侧递归 → **平均 O(n)**，原地，但会改变原数组且最坏 O(n²)；
4. **计数/桶**：数据范围小或分布已知时 O(n)；
5. 海量（内存放不下）：**分治 + 归并**（按哈希分到多个文件，各自 TopK 再合并）、**MapReduce**、或位图/布隆过滤器预处理。

> 变形：第 K 大 = 小顶堆（堆顶即答案）；第 K 小 = 大顶堆。中位数 = 双堆（大顶堆存较小一半 + 小顶堆存较大一半，保持平衡）。

**Q11：常用位运算技巧？**

**A：**

| 技巧 | 写法 | 作用 |
| --- | --- | --- |
| 判奇偶 | `n & 1` | 比 `% 2` 快 |
| 消去最低位的 1 | `n & (n - 1)` | **统计 1 的个数**、判断 2 的幂（`n & (n-1) === 0`） |
| 取最低位的 1 | `n & -n` | lowbit（树状数组） |
| 异或性质 | `a ^ a = 0`、`a ^ 0 = a` | **只出现一次的数字**、交换两数（不推荐可读性差） |
| 乘除 2 | `n << 1` / `n >> 1` | 注意溢出与符号 |
| 取第 k 位 | `(n >> k) & 1` | 状态压缩 DP |
| 置位/清位 | `n \| (1 << k)` / `n & ~(1 << k)` | 权限位掩码 |
| 取绝对值 | `(n ^ (n >> 31)) - (n >> 31)` | 32 位整数 |

> 坑：JS 位运算把操作数转成 **32 位有符号整数**，`1 << 31` 是负数、`2 ** 32` 运算会截断，大整数要用 `BigInt`。

**Q12：海量数据问题（大文件去重、统计、排序）怎么解？**

**A：** 核心思路是「**分而治之 + 合适的数据结构压缩**」：

1. **哈希分片**：按 `hash % N` 把大文件拆成 N 个小文件，分别处理再归并（相同 key 一定落到同一文件）；
2. **位图 BitMap**：40 亿个不重复整数判重 → 用 2^32 bit ≈ 512MB；
3. **布隆过滤器**：允许误判时用极少内存判"一定不存在"；
4. **堆 + 归并**：多路归并排序处理超过内存的文件（外部排序，数据库排序和 MapReduce 都这么干）；
5. **Trie / 前缀统计**：统计高频词、前缀查询；
6. **HyperLogLog**：UV 这类近似统计，固定 12KB。

经典题：① 大文件中找出现次数最多的 IP（哈希分片 + HashMap 统计 + 堆合并 TopK）；② 两个 50 亿 URL 文件求交集（布隆过滤器 + 分片）；③ 10 亿整数找中位数（分桶统计各区间计数，定位到桶后再精确处理）。
