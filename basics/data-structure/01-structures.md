# 数据结构通识

---

**Q1：数组和链表的区别？怎么选？**

**A：**

| 维度 | 数组 | 链表 |
| --- | --- | --- |
| 内存 | **连续** | 分散，靠指针串 |
| 随机访问 | O(1)（下标寻址） | O(n) |
| 插入删除 | O(n)（要搬移） | O(1)（已知前驱） |
| 缓存友好 | ✅ 命中率高（连续） | ❌ 指针跳转，Cache 命中差 |
| 空间 | 紧凑 | 每个节点多存 1~2 个指针 |
| 扩容 | 需要搬移（均摊 O(1)） | 天然动态 |

选型：读多写少、需要随机访问 → 数组（Java `ArrayList`、V8 快数组）；频繁在中间增删、无需随机访问 → 链表（`LinkedList`、LRU 的手写双向链表）。工程上**数组几乎总是更快**，因为缓存局部性；链表优势主要体现在"删除已知节点 O(1)"和不需要连续内存。

**Q2：哈希表是怎么工作的？冲突怎么解决？**

**A：** 用**哈希函数**把 key 映射到数组下标，`index = hash(key) % capacity`，理想情况 O(1)。

冲突解决：

1. **链地址法**（Java HashMap、Redis dict）：冲突的元素挂成链表/红黑树（Java 8 链表长度 >8 且容量 ≥64 转红黑树）；
2. **开放地址法**（线性探测、二次探测、双哈希；Python dict、ThreadLocalMap）：冲突就往后找空位，缓存友好但删除要打墓碑标记，且装载因子必须低。

**扩容**：装载因子 `size/capacity` 超阈值（Java 0.75）时扩容到 2 倍并 rehash，单次 O(n) 但**均摊 O(1)**。Redis 用渐进式 rehash 避免卡顿。

> 一个好的哈希函数要：**快速 + 分布均匀 + 抗碰撞**。扰动函数（Java 的 `h ^ (h >>> 16)`）是为了让高位也参与运算，减少碰撞。

**Q3：二叉搜索树（BST）的问题？为什么需要平衡树？**

**A：** BST 满足「左 < 根 < 右」，查找/插入/删除平均 O(log n)。但**退化**风险：按有序序列插入 1,2,3,4,5 会变成一条链表，复杂度降到 O(n)。

解决办法是**自平衡**：

- **AVL 树**：严格平衡（任一节点左右子树高度差 ≤1），查询最快，但插入删除要频繁旋转，适合**读多写少**；
- **红黑树**：**近似平衡**（最长路径 ≤ 2×最短路径），插入删除最多 2~3 次旋转，综合性能更好 → `TreeMap`、`std::map`、Linux CFS 调度、epoll 就绪队列都用它；
- **Treap/Splay/B 树族**各有场景。

> 红黑树 5 条性质：①节点非红即黑；②根黑；③叶子(NIL)黑；④红节点的孩子必黑（不能连续红）；⑤任一节点到其所有后代 NIL 的黑节点数相同。

**Q4：红黑树和 B+ 树分别在什么场景用？为什么？**

**A：**

- **红黑树**：内存中的有序结构，树高 `log2(n)`，10 万数据约 17 层，节点指针跳转对 Cache 不友好但都在内存里，无所谓 → 适合**内存索引**（`std::map`、Java `TreeMap`、进程调度）。
- **B+ 树**：为**磁盘/SSD**设计，多路（一个节点上千个 key）把树高压到 3~4 层，**树高 = IO 次数**；叶子用链表相连，范围查询一次定位后顺序扫 → 适合**数据库与文件系统索引**。

一句话：**红黑树优化的是比较次数，B+ 树优化的是 IO 次数。**

**Q5：堆（优先队列）是什么？怎么用？**

**A：** 堆是**完全二叉树**的数组实现，满足堆性质（大顶堆：父 ≥ 子）。下标关系：`parent=(i-1)/2`、`left=2i+1`、`right=2i+2`。

- 插入 `sift up` O(log n)；弹堆顶 `sift down` O(log n)；建堆 O(n)（自底向下 sift down）；取最值 O(1)。
- 应用：**TopK**（小顶堆，堆大小固定为 K，遍历一遍 O(n log K)）、**优先队列**（任务调度、Dijkstra、 Huffman）、**堆排序**、**合并 K 个有序链表**。
- 工程变体：**d 叉堆**（Java `PriorityQueue` 是二叉堆）、**索引堆**（支持改值）、**定时器时间轮/最小堆**（Nginx、Netty 的定时任务）。

**Q6：图的存储方式与遍历？**

**A：**

- **邻接矩阵** `matrix[i][j]`：查两点是否相邻 O(1)，空间 O(V²) → 适合**稠密图**；
- **邻接表**：每个顶点挂一个链表/数组，空间 O(V+E) → 适合**稀疏图**（绝大多数场景）；
- **BFS**（队列 + visited）：逐层扩散，最短路径（无权图）、层序遍历；
- **DFS**（栈/递归 + visited）：一条路走到底，适合连通性、拓扑排序、回溯找路径。

> 注意：图可能成环，**visited 必不能少**；递归 DFS 深图会栈溢出，改成显式栈。

**Q7：Trie（前缀树）是什么？用在哪？**

**A：** 每个节点存一个字符，从根到某节点的路径构成一个字符串，公共前缀共享节点。

- 插入/查询 O(L)（L 为字符串长度），与数据量无关；
- 空间换时间：字符集大时（如中文）用 map 存子节点（而非定长数组）或改用三分支 Trie；
- 应用：**搜索框自动补全**、**敏感词/前缀匹配**、路由表最长前缀匹配、拼写检查。

> 变体：**压缩 Trie/Radix Tree**（路径压缩，Redis 的 rax、Linux 基数树）；**AC 自动机** = Trie + fail 指针，多模式串匹配（敏感词过滤）。

**Q8：并查集（Union-Find）是什么？怎么优化？**

**A：** 处理「**连通性**」与「**集合合并**」问题，支持两个操作：`find(x)` 找代表元、`union(x, y)` 合并集合。

两大优化（都做：复杂度接近 O(α(n))，可视为 O(1)）：

1. **路径压缩**：`find` 时把沿途节点直接挂到根上；
2. **按秩/按大小合并**：小树挂到大树下，避免树退化成链。

应用：岛屿数量、朋友圈、`Kruskal` 最小生成树、动态连通性、编译器的寄存器分配、图的连通分量。

**Q9：跳表（Skip List）是什么？和平衡树比？**

**A：** 在**有序链表**上抽若干层索引（每个节点以概率 1/2 晋升到上一层），查找时从最高层往右走、走不动就下降一层，时间 O(log n)。

- 优点：实现简单（不用旋转）、范围查询天然顺着底层链表扫、**插入删除只改局部指针**、并发友好（无锁跳表）；
- 缺点：空间多一倍左右、依赖随机（不保证最坏情况）；
- 应用：**Redis ZSet**、LevelDB/RocksDB 的 MemTable、Lucene 的倒排（变体）。

**Q10：布隆过滤器（Bloom Filter）的原理与误判？**

**A：** 一个 m 位的位数组 + k 个独立哈希函数。插入：把 k 个哈希位置置 1；查询：k 位全 1 则**可能存在**，任一位为 0 则**一定不存在**。

- 特性：**有误判率（假阳性），绝无假阴性**；不支持删除（多位共用）→ 计数布隆过滤器（CBF）或 Cuckoo Filter 可删。
- 误判率公式近似：`p ≈ (1 - e^(-kn/m))^k`，最优 `k = (m/n) ln2`；取 `m/n = 10` 时误判约 1%。
- 应用：**缓存穿透防护**、爬虫 URL 去重、垃圾邮件过滤、HBase/Cassandra 的 SSTable 快速判否、Redis 的 `RedisBloom` 模块。

**Q11：栈、队列、双端队列、单调栈/单调队列各自解决什么问题？**

**A：**

- **栈**（后进先出）：函数调用、括号匹配、表达式求值、DFS、撤销（undo）；
- **队列**（先进先出）：BFS、缓冲区、任务排队、生产者消费者；
- **双端队列 Deque**：滑动窗口（`单调队列`）、`ArrayDeque`（Java 推荐替代 `Stack` 和 `LinkedList`）；
- **单调栈**：栈内元素保持有序，用于「**下一个更大元素**」「柱状图最大矩形」「接雨水」，每个元素进出栈各一次 → O(n)；
- **单调队列**：队首即当前窗口最值 → **滑动窗口最大值** O(n)。

**Q12：如何为场景选择数据结构？**

**A：** 按操作倒推：

| 需求 | 选择 |
| --- | --- |
| 快速按 key 查值 | 哈希表 |
| key 需要有序 / 范围查询 | 红黑树、跳表（内存）／B+ 树（磁盘） |
| 只关心最大/最小、TopK | 堆 |
| 前缀匹配 | Trie |
| 集合连通/合并 | 并查集 |
| 存在性判否、容忍误判 | 布隆过滤器 |
| LRU 缓存 | 哈希表 + 双向链表（O(1) 查找 + O(1) 移动） |
| 区间统计/前缀和 | 前缀和数组、线段树、树状数组 BIT |
| 大量字符串去重/计数 | 哈希 / HyperLogLog（近似） |

> 组合使用才是常态：LRU = 哈希表 + 链表；数据库索引 = B+ 树 + 缓冲池哈希；Redis ZSet = 跳表 + 哈希表。
