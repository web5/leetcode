## 一、定义与本质

> 动态规划 = 把「多阶段决策问题」的解，表示为**有限个状态的函数**，并利用**状态之间的递推关系**（转移方程）求出答案。

拆成三句：

1. **有阶段**：问题可以按某种顺序（天 / 物品 / 区间长度 / 位数）逐步决策；
2. **有状态**：每一步只需要记住一个**有限描述**（而不是完整历史）；
3. **能递推**：后面的状态可以由前面的状态算出来，且**会被重复用到**。

**本质一句话**：把「指数多条路径」按状态压成「多项式个格子」，每个格子只保留对后续有用的那个值（最优 / 计数 / 布尔）。

> 例：`dp-122` 里 `hold` 从 `-7` 跳到 `-1`，不是 -7 凭空消失，而是「第 0 天 7 元买入」这条历史被「第 1 天 1 元买入」那条**支配**了（同状态、同未来、常数差 6 永远消不掉），于是被剪枝。DP 快就快在这台剪枝引擎。

## 二、成立的三个条件

| 条件 | 含义 | 违反会怎样 |
|---|---|---|
| **最优子结构** | 原问题的最优解由子问题的最优解拼成 | 子问题最优推不出全局最优，DP 失效（如带环图上的最长路径） |
| **无后效性**（Markov 性） | 未来只依赖状态的**值**，不依赖「怎么走到这个状态」 | 状态漏信息 → 答案错，必须补维度 |
| **重叠子问题** | 同一子问题被反复求解 | 只影响「值不值得 DP」；不重叠就是普通分治（归并排序） |

最常出事的是**无后效性**。判断法：

> 两个局面，如果「之后能做的操作」和「之后能拿到的收益」完全相同，它们就是同一状态，可以合并（只留更优的那个值）。

`dp-122` 的 `(第 i 天, 持有一股)` 与 `(第 i 天, 空仓)` 就是按这个判据切出来的。

## 三、五个要件（写 DP 的固定动作）

| # | 要件 | 说明 |
|---|---|---|
| ① | **状态定义** | 一句话说清 `dp[...]` 的含义，必须满足无后效性 |
| ② | **边界 / 初值** | 递推起点，要符合物理含义；不可达状态用 `-Infinity` / `Infinity` 表示 |
| ③ | **转移方程** | 穷举到达该状态的**所有**来路，不重不漏 |
| ④ | **递推顺序** | 按拓扑序（用到的子问题必须已算好） |
| ⑤ | **答案位置** | 哪个状态是最终答案 |

③ 的通用手法是**「最后一步法」**：

> 问自己：**到达这个状态前的最后一步，可能做了什么？** 把所有可能列完，就是转移方程。

122 里最后一步只有两种：昨天持有今天不动 / 昨天空仓今天买入 —— 没有第三类，所以两项写全了。

## 四、两种实现范式

| | 自顶向下（记忆化搜索） | 自底向上（递推填表） |
|---|---|---|
| 形态 | 递归 + `memo` | 循环 + `dp` 数组 |
| 优点 | 只算用得到的状态；贴近暴力搜索，好想 | 无栈溢出风险；便于滚动数组；常数小 |
| 缺点 | 递归深度受限；常数大；不便空间压缩 | 需自己排顺序；可能算了不需要的状态 |

**等价性**：两者算的是同一个东西，`memo` 就是 DP 表的另一种填充顺序。**先写记忆化版本再改写成循环**，是最稳的学习路径。

### 空间压缩（滚动数组）

转移只依赖「上一层」时，可丢掉历史维度。一维原地更新要注意遍历方向：

- 0-1 背包：**倒序**（防同一物品用多次）
- 完全背包：**正序**（允许重复使用）

122 更极致：只依赖前一天的 `cash`（即临时变量 `preCash`），两个变量搞定，`O(1)` 空间。

## 五、分类图谱

### 按状态维度

| 维度 | 典型状态 | 例题 |
|---|---|---|
| 1D 线性 | `dp[i]` = 前 i 个的最优 | 70 爬楼梯、198 打家劫舍、121/122 股票 |
| 2D | `dp[i][j]` = 前 i 个物品、容量 j | 背包、LCS、编辑距离 |
| 区间 | `dp[i][j]` = 区间 `[i, j]` 的最优 | 516 最长回文子序列、312 戳气球 |
| 树形 | `dp[u][0/1]` = 以 u 为根的子树 | 337 打家劫舍 III |
| 状态压缩 | `dp[mask]` = 已选集合为 mask | 状压棋盘、TSP |
| 数位 | `dp[pos][...]` = 第 pos 位的计数 | 数位 DP |
| 概率 / 期望 | `dp[state]` = 期望值 | 808 汤分汤 |

### 按目标（决定转移里的运算）

| 目标 | 运算 | 代数视角 |
|---|---|---|
| 求最优 | `max` / `min` | max-plus |
| 求方案数 | `+`（配 `*`） | 计数半环 |
| 求可行性 | 布尔 or / and | 布尔半环 |
| 求具体方案 | 额外记录「决策来源」再回溯 | — |

**重要**：`max` 不是 DP 的标志，「按状态取极值」只出现在最优性 DP 里。爬楼梯的 `dp[i] = dp[i-1] + dp[i-2]` 一个 `max` 没有，照样是 DP。

### 按转移写法

- **填表法（pull）**：`dp[i]` 由前面的算出来（122 现在这样）
- **刷表法（push）**：用 `dp[i]` 去更新 `dp[i+1]`

## 六、建模方法论

1. **找阶段**：按什么顺序推进？（天 / 物品 / 区间长度 / 位数）
2. **找决策**：每阶段做什么选择？（买/卖、选/不选、切/不切）
3. **问「我需要记住什么」**：为了后续决策，最少要记住哪些信息？这就是状态维度。**记多了冗余，记少了有后效性。**
4. **验无后效性**：状态相同的局面，未来是否完全一样？
5. **用最后一步法写转移**。
6. **定初值与递推序**，明确答案在哪个格子。
7. **算复杂度**：时间 = 状态数 × 单状态转移代价；空间 = 状态数（可压缩）。

**加维度消除后效性**是标准手法。122 若只写 `dp[i]` = 前 i 天最大利润，就不知道「现在手里有没有货」，无法判断第 i+1 天能否卖出 → 补一个 `持有/空仓` 维度。

### 统一视角：DP 就是 DAG 上的值传播

状态是顶点，转移是有向边，整个状态空间是一张 **DAG**，DP = 按拓扑序做值传播。

| 算法 | 在 DP 视角下 |
|---|---|
| 记忆化搜索 | 自顶向下 DP |
| 贪心 | 极端特例：每步只剩一条值得走的路（122 的差分贪心：`max` 退化成「只留正差分」） |
| Dijkstra | 图上 DP，`dist[v] = min(dist[v], dist[u] + w)`，用优先队列代替拓扑序 |
| Bellman-Ford | 允许反复松弛的图上 DP（可处理负边） |
| 分治 | 子问题**不重叠**的「分」；DP 是子问题**重叠**的「合」 |

## 七、常见错误清单

| 错误 | 症状 | 修正 |
|---|---|---|
| 状态漏信息 | 少数用例错 | 补维度（如 LIS 只记长度不记末尾值） |
| 状态冗余 | 复杂度过高但答案对 | 合并等价状态、滚动数组、证明支配关系 |
| 初值错 | 边界用例错 | 区分「0 是合法值」与「0 被误当成合法值」——122 用 `-Infinity` 正是此坑 |
| 转移漏项 | 少了 `max` 那类 bug | 最后一步法穷举所有来路 |
| 用错旧值 | 同一天重复交易 / 物品用两次 | 临时变量存 `preCash`；背包倒序 |
| 顺序错 | 结果随机或偏大 | 确认拓扑序；区间 DP 按长度递增 |
| 原地覆盖 | 滚动数组后答案变了 | 检查依赖方向，决定正序/倒序 |

## 八、与相邻概念的分界

- **DP vs 贪心**：贪心是「每步局部最优 ⇒ 全局最优」，需要交换论证背书；DP 是保留所有可能状态再取最优。贪心可看作 DP 剪枝到只剩一条路径。122 两者都成立（题目给了三个特权条件），一旦加手续费/冷冻期，贪心立刻崩。
- **DP vs 回溯 / 暴力**：暴力枚举路径，DP 按状态合并路径 —— 差别就在「要不要记住路径怎么来」。
- **DP vs 分治**：都靠子问题拼答案，区别只在子问题是否重叠。
- **DP vs 最短路**：同一数学模型（Bellman 方程）。

## 十、本目录题目索引

### 10.1 母题演化：一次 → 无限次 → k 次

| 题号 | 文件 | 导出函数 | 交易限制 |
|---|---|---|---|
| 121 | [dp-121.js](./dp-121.js) | `maxProfitOnce` | 只允许 **1 次** |
| 122 | [dp-122.js](./dp-122.js) | `maxProfitInfinite` | **无限次** |
| 188 | [dp-188.js](./dp-188.js) | `maxProfitK` | 最多 **k 次** |

**演化关系**：121 是 `k = 1`；122 相当于 `k ≥ n/2`（此时次数不再是约束，188 里就靠这个分支退化成 122 的差分贪心）。

**三者状态/转移对照**：

| 题 | 状态定义 | 转移 | 边界 | 答案 |
|---|---|---|---|---|
| 121 | `hold` = 持股成本（负数）；`cash` = 已实现最大利润 | `hold = max(hold, -p)`<br>`cash = max(cash, hold + p)` | `hold = -Infinity`<br>`cash = 0` | `cash` |
| 122 | 同上，但可无限次交易 | `hold = max(hold, preCash - p)`<br>`cash = max(cash, hold + p)` | `hold = -Infinity`<br>`cash = 0` | `cash` |
| 188 | `buy[j]` = 第 j 笔已开仓的利润；`sell[j]` = 已完成 j 笔且空仓的利润 | `sell[j] = max(sell[j], buy[j] + p)`<br>`buy[j] = max(buy[j], sell[j-1] - p)` | `buy[j] = -Infinity`<br>`sell[j] = 0` | `sell[k]` |

**一句话看懂 121 与 122 的唯一差别**：

```
121 的买入只能用初始资金（0）：   hold = max(hold, 0 - p)      → 常数 -p
122 的买入可用已落袋利润：        hold = max(hold, preCash - p) → preCash - p
```

`preCash - p` 那一项就是「允许把已实现的利润拿来重新建仓」——这正是「无限次」在公式上的全部体现。而它对应的现实动作，就是贪心里的「在同一天卖了又买回」。

### 10.2 121 的实现说明

`dp-121.js` 用的是**等价变形**：不显式维护 `hold`，而是用 `minPrice`（等于 `-hold` 的另一种记法），边遍历边更新最小买入价并计算 `price - minPrice`。两种写法完全等价，只是把「维护最大利润」换成「维护最低成本」。

### 10.3 122 的实现说明

主解是 DP（`maxProfitInfinite`），文件末尾保留了差分贪心版本 `maxProfitGreedy` 及完整论证。结论：**122 两者都对**，但只有 DP 能平滑迁移到 123/188/309/714。

### 10.4 188 的实现说明

- `k >= floor(n/2)` 时次数约束失效 → 退化为 122，直接用差分贪心（`O(n)`）。
- 否则用 `buy[k+1]` / `sell[k+1]` 两组滚动数组，天数为外层、交易笔数为内层，`O(nk)`。
