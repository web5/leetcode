# 操作系统 · 进程与线程

---

**Q1：进程和线程的区别？**

**A：**

| 维度 | 进程 | 线程 |
| --- | --- | --- |
| 定义 | 资源分配的基本单位 | CPU 调度的基本单位 |
| 地址空间 | 独立虚拟地址空间 | 共享所属进程的地址空间 |
| 私有资源 | 全部独享 | 独享：栈、寄存器（PC/SP）、线程局部存储 TLS、errno、调度优先级 |
| 共享资源 | IPC 才能共享 | 共享：堆、全局变量、文件描述符表、信号处理方式、代码段 |
| 切换成本 | 高（要切页表 CR3、刷 TLB、内核栈） | 低（地址空间不变，只换栈和寄存器） |
| 健壮性 | 一个进程崩了不影响别人 | 一个线程崩（如段错误）会带崩整个进程 |

> *代价/坑*：线程共享 FD，一个线程 `close(fd)` 会影响其他线程；`fork` 只复制调用线程，其他线程消失 → 多线程里 fork 极易死锁（malloc 锁）。

---

**Q2：为什么要有线程？进程不够用吗？**

**A：** 并发场景越来越密（一个 Web 服务同时处理上万连接），用多进程有三大痛点：① 创建/销毁与上下文切换开销大；② 进程间通信必须走内核（管道/共享内存/消息队列），成本高；③ 数据共享麻烦。线程共享地址空间，创建快、切换轻、通信直接读写共享变量。代价是引入同步问题（竞态、死锁）与隔离性变差。

---

**Q3：协程是什么？和线程、进程比有什么不同？**

**A：** 协程是**用户态**的轻量级"线程"，由程序自己调度，切换只保存/恢复少量寄存器和栈，不进内核、不触发上下文切换，成本约几十纳秒（线程切换约微秒级）。

- **对比线程**：线程是内核调度、抢占式（时间片到就换）；协程是协作式，只有主动 `yield`/`await` 才让出。
- **优势**：单机能开几十万协程；无锁编程（同一线程内串行）；异步代码写得像同步。
- **代价**：一个协程阻塞（如同步文件 IO、CPU 密集计算）会卡死同线程所有协程 → 所有阻塞调用必须换成非阻塞/异步版本。
- 代表：Go goroutine（有抢占，M:N 调度）、Kotlin/JS `async/await`、Python `asyncio`。

---

**Q4：进程间通信（IPC）有哪些方式？**

**A：**

| 方式 | 原理 | 特点 |
| --- | --- | --- |
| 管道 pipe | 内核环形缓冲区，字节流 | 半双工、只能亲缘进程；`|` 就是匿名管道 |
| 命名管道 FIFO | 文件系统中有名字 | 无关进程也能用，仍是单向字节流 |
| 信号 signal | 内核通知（如 `SIGKILL`） | 只传编号，不能带数据；异步 |
| 消息队列 | 内核维护的链表，带类型 | 有格式、可随机读；但用户态↔内核态拷贝开销大 |
| 共享内存 | 多进程映射同一块物理内存 | **最快**（无需内核拷贝），但要配信号量/互斥量做同步 |
| 信号量/PV | 计数器 + 阻塞唤醒 | 用于同步互斥，不传数据 |
| socket | 走网络协议栈，可跨机 | 最通用，也最慢（多次拷贝 + 协议栈） |

> 追问"最快的 IPC"：共享内存；"为什么还要用 socket"：可以跨机器、天然支持不同语言/主机。

**Q5：进程的五种状态与状态转换？**

**A：** 新建（new）→ 就绪（ready）↔ 运行（running）→ 阻塞/等待（waiting）→ 终止（terminated）。

- 就绪→运行：被调度器选中；
- 运行→就绪：时间片用完 / 被更高优先级抢占；
- 运行→阻塞：等待 IO、等锁、`sleep`；
- 阻塞→就绪：IO 完成 / 锁释放（**不会**直接回到运行态）；
- 挂起（suspend）是进阶状态：进程被换出到磁盘（阻塞挂起、就绪挂起）。

**Q6：常见进程调度算法？**

**A：**

- **FCFS 先来先服务**：简单，长作业会导致短作业等待过久（护航效应）；
- **SJF/短作业优先**：平均等待时间最优，但长作业可能饿死，且需预知运行时间；
- **RR 时间轮转**：时间片轮转，公平、适合交互式；时间片太大退化成 FCFS，太小切换开销爆炸（通常 10~100ms）；
- **优先级调度**：可能饿死低优先级 → 用**老化**（aging）动态提升等待久的进程优先级；
- **多级反馈队列（MLFQ）**：多个 RR 队列，优先级递减、时间片递增；新进程进高优先级，用完时间片降级，等待久则升级 —— 兼顾响应与吞吐，是真实 OS（Linux CFS 思路近似）常用方案；
- **Linux CFS**：完全公平调度，用 `vruntime`（虚拟运行时间）红黑树，总是挑 vruntime 最小的跑，不靠固定时间片。

**Q7：上下文切换到底切了什么？**

**A：** 保存当前任务的执行现场，恢复下一个任务的现场：
① 通用寄存器、程序计数器 PC、栈指针 SP；
② 内核栈；
③ 进程切换还要切**页表基址寄存器（x86 的 CR3）**，导致 TLB 几乎全部失效；
④ 刷新/更新内核数据结构（PCB、就绪队列）；
⑤ 用户态↔内核态切换本身（系统调用、特权级切换）。

> 追问：为什么进程切换比线程切换贵？—— 主要是页表切换 + TLB 失效 + Cache 冷启动。

**Q8：僵尸进程和孤儿进程？**

**A：**

- **僵尸进程**：子进程退出后，内核保留其 PCB（退出码、统计信息）等父进程 `wait()` 回收；父进程一直不回收，PCB 就一直占着进程表项（状态 `Z`）。危害：PID 资源泄漏，进程表满了无法创建新进程。解决：父进程 `wait/waitpid`，或注册 `SIGCHLD` 处理函数（`signal(SIGCHLD, SIG_IGN)` 让内核直接回收）；杀掉父进程后僵尸被 init(pid 1) 领养并回收。
- **孤儿进程**：父进程先退出，子进程被 init/systemd（pid 1）领养，正常收尸，**无害**。

**Q9：`fork()` 之后子进程拿到的是什么？写时复制（COW）是什么？**

**A：** `fork` 后子进程获得：独立的虚拟地址空间（初始内容与父进程相同）、独立 PID、父进程的 FD 表副本（共享同一文件表项/偏移量）、信号处理方式。父子通过返回值区分（父得到子 pid，子得到 0）。

**写时复制**：现代 `fork` 不真的复制物理内存，而是把父子页表项都指向同一物理页并标记为只读；任一方写入时触发缺页异常，内核才分配新页、复制内容、改为可写。好处：`fork` 极快，`fork + exec` 场景中完全避免了无谓拷贝。

---

**Q10：`fork` 的返回值为什么有两个？**

**A：** 因为调用一次返回两次：在父进程中返回子进程 PID（用于 `waitpid`），在子进程中返回 0（`getpid()` 能拿到自己，`getppid()` 拿父进程）。失败时父进程返回 -1，无子进程。

---

**Q11：用户态和内核态的区别？什么时候会切换？**

**A：** 内核态（ring 0）可执行特权指令、访问全部内存；用户态（ring 3）受限，只能访问自己的用户空间。

切换时机：① 系统调用（`read/write/fork`，通过 `syscall`/软中断陷入）；② 中断（时钟、IO 完成）；③ 异常（缺页、除零、非法指令）。

一次系统调用的完整开销：陷入 → 保存现场 → 切内核栈 → 权限检查 → 参数校验（用户指针要检查） → 执行 → 返回用户态，约几百纳秒到 1 微秒。这就是"减少系统调用次数"是性能优化常见手段的原因（如缓冲写、`epoll` 取代 `select`）。

---

**Q12：进程、线程、协程的选择依据？**

**A：**

- 需要**强隔离 / 跨机 / 语言异构** → 多进程（Nginx master-worker、Chrome 多进程渲染、pm2 cluster）；
- 需要**共享大量数据 + 多核并行计算** → 多线程；
- 需要**高并发 IO、连接数巨大** → 事件循环 + 协程/异步（Node、Go、Redis 单线程 + epoll）；
- **CPU 密集** → 线程/进程数 ≈ CPU 核数，协程帮不上忙，得靠多核并行或换语言/算法。
