# 121. 买卖股票的最佳时机（简单）

> https://leetcode.cn/problems/best-time-to-buy-and-sell-stock/
> 标签：数组、动态规划
> 答案：[solutions/121-best-time-to-buy-and-sell-stock.js](../../solutions/121-best-time-to-buy-and-sell-stock.js)

## 题目描述

给定一个数组 `prices`，它的第 `i` 个元素 `prices[i]` 表示一支给定股票第 `i` 天的价格。

你只能选择 **某一天** 买入这只股票，并选择在 **未来的某一个不同的日子** 卖出该股票。设计一个算法来计算你所能获取的最大利润。

返回你可以从这笔交易中获取的最大利润。如果你不能获取任何利润，返回 `0`。

## 示例

**示例 1：**
- 输入：`[7,1,5,3,6,4]`
- 输出：`5`
- 解释：在第 2 天（股票价格 = 1）的时候买入，在第 5 天（股票价格 = 6）的时候卖出，最大利润 = 6-1 = 5。注意利润不能是 7-1 = 6，因为卖出价格需要大于买入价格；同时，你不能在买入前卖出股票。

**示例 2：**
- 输入：`[7,6,4,3,1]`
- 输出：`0`
- 解释：在这种情况下，没有交易完成，所以最大利润为 0。

## 提示

- `1 <= prices.length <= 10^5`
- `0 <= prices[i] <= 10^4`

## 思路：状态压缩 DP

表面上是"一次遍历维护历史最低价"的贪心，本质是二维 DP 压缩掉一维后的形态。

### 1. 状态定义

每天盘后只可能处于两种情形，且**决定未来的信息只有「手里有没有股票」**：

| 状态 | 含义 |
| --- | --- |
| `dp[i][0]` | 第 i 天结束时**不持有**股票，能达到的最大收益 |
| `dp[i][1]` | 第 i 天结束时**持有**股票，能达到的最大收益（即已花出去的钱的负数） |

不需要记录"哪天买的"——只要知道持有状态，未来收益 = `卖价 - 买价`，而买价已被压进 `dp[i][1]` 的数值里。这就是**无后效性**：历史细节被压缩进状态值，不需要额外维度。

### 2. 状态转移

每天只有「不动 / 买入 / 卖出」三种动作：

```
dp[i][0] = max(dp[i-1][0],          // 昨天就不持有，今天不动
               dp[i-1][1] + p[i])   // 昨天持有，今天卖出

dp[i][1] = max(dp[i-1][1],          // 昨天就持有，今天不动
               -p[i])               // 今天才买入
```

注意买入项是 **`-p[i]`，不是 `dp[i-1][0] - p[i]`** —— 这正是"**只交易一次**"的体现：买入前不允许有任何收益（不能先卖再买），而 `dp[i-1][0]` 在首次卖出前恒为 0，故直接写 `-p[i]`。

### 3. 初始化与边界

```
dp[0][0] = 0            // 第一天不买
dp[0][1] = -prices[0]   // 第一天买入
```

`debug-121.js` 用 `minPrice = Infinity` 且先算收益、后更新最小值，等价于把 `dp[-1]` 当"还没开始"的哨兵状态，省掉对 `prices[0]` 的特判，同时天然保证买、卖不在同一天。

### 4. 遍历顺序与答案

按天正序递推（`i` 从 0 到 n-1），因为 `dp[i]` 只依赖 `dp[i-1]`。

答案为 `dp[n-1][0]`（最后必须落袋为安）；题目要求利润不能为负，故与 0 取 max —— 代码里 `maxProfit` 初始化为 `0` 正好兼顾这一点。

### 5. 空间压缩：为什么两个变量就够

```
dp[i][1] = -min(prices[0..i])
```

令 `minPrice = -dp[i][1]`，代入 `dp[i][0]`：

```
dp[i][0] = max(dp[i-1][0], prices[i] - minPrice)
```

二维数组坍缩成两个标量，即 `solutions/121-best-time-to-buy-and-sell-stock.js` 中的 `maxProfit`（=`dp[i][0]`）与 `minPrice`（=`-dp[i][1]`）。

### 6. 手推 `[7,1,5,3,6,4]`

| i | price | minPrice | `dp[i][0]` |
| --- | --- | --- | --- |
| 0 | 7 | 7 | 0 |
| 1 | 1 | 1 | 0 |
| 2 | 5 | 1 | 4 |
| 3 | 3 | 1 | 4 |
| 4 | 6 | 1 | **5** |
| 5 | 4 | 1 | 5 |

复杂度：时间 O(n)，空间 O(1)。

## 分析任意 DP 题的通用五问

1. **状态**：处境由哪几个量决定？（本题：第几天 + 是否持有）→ 问"要做出下一步决策，最少需要知道什么信息"，多一个必要信息就多一维。
2. **转移**：上一步到这一步有哪些**动作**可选？（不动 / 买 / 卖）每个动作对应一条公式。
3. **初始化**：第 0 天、规模为 0、空集合时是什么？涉及 min 用 `Infinity`，max 用 `-Infinity`，求和用 `0`。
4. **遍历顺序**：谁依赖谁？依赖必须先算 → 决定正序 / 倒序 / 斜序。
5. **答案**：落在哪个状态上？（本题 `dp[n-1][0]`，不是所有状态的 max）

补充三问做校验：

6. **无后效性**：状态里是否包含了所有影响未来的信息？反例：若允许"先卖后买"，就必须加"已交易次数"维度。
7. **边界 / 非法状态**：题目约束（必须不同日、利润可为 0）在转移里体现了吗？
8. **能否压缩**：`dp[i]` 只依赖 `dp[i-1]` 且只用到单向旧值 → 可降维。

## 股票系列的状态维度对照

| 题 | 状态维度 | 差异点 |
| --- | --- | --- |
| 121 | 天 + 是否持有 | 只能买一次 → 买入项写 `-p[i]` |
| 122 | 天 + 是否持有 | 可无限次交易 → 买入项写 `dp[i-1][0] - p[i]` |
| 123 / 188 | 天 + 是否持有 + **已交易次数** | 再加一维 k，`dp[i][k][0/1]` |

121 把股票 DP 的骨架暴露得最干净：两个状态如何互相咬合。122 只是把买入项替换成 `dp[i-1][0] - p[i]`，123 / 188 只是外面再套一层 k 的循环。

## 踩坑记录

- 曾经用 `minIndex === prices.length - 1` 来兜底"最低价出现在最后一天则无法卖出"，结论错误：反例 `[1, 100, 0]`，最低价 0 在最后一天，但正确答案是 99（第 1 天买、第 2 天卖）。该判断可整段删除 —— `maxProfit` 初始为 0 + `Math.max` 已天然保证"不能获利返回 0"。
- 循环内应**先**用旧 `minPrice` 计算收益、**再**更新 `minPrice`，语义上才符合"未来的某一个不同日子"。顺序反过来数值通常也对（同日买卖利润为 0），但表达不严谨。
