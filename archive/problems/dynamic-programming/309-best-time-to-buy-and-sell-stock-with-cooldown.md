# 309. 最佳买卖股票时机含冷冻期（中等）

> https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-with-cooldown/
> 标签：数组、动态规划
> 答案：[solutions/309-best-time-to-buy-and-sell-stock-with-cooldown.js](../../solutions/309-best-time-to-buy-and-sell-stock-with-cooldown.js)
> 族谱：[dp/README.md §10.5 股票族一刷脚本与迁移表](../../dp/README.md)（122 的「交易成本维」另一支）

## 题目描述

给定一个整数数组 `prices`，其中第 `prices[i]` 表示第 `i` 天的股票价格。

设计一个算法计算出最大利润。在满足以下约束条件下，你可以尽可能地完成更多的交易（多次买卖一支股票）：

- 卖出股票后，你无法在第一天卖出股票并在第二天买入股票（即冷冻期为 `1` 天）。

**注意：** 你不能同时参与多笔交易（你必须在再次购买前出售掉之前的股票）。

## 示例

**示例 1：**
- 输入：`prices = [7,1,5,3,6,4]`
- 输出：`5`
- 解释：在第 2 天（价格 = 1）买入，在第 5 天（价格 = 6）卖出，利润 = `6 - 1 = 5`。
  （对比：同一数组在 122（无冷冻期）下是 `7`，冷冻期让你损失 2）

**示例 2：**
- 输入：`prices = [1,2,3,0,2]`
- 输出：`3`
- 解释：在第 1 天（价格 = 1）买入，第 2 天（价格 = 2）卖出（利润 1），冷冻一天，第 4 天（价格 = 0）买入，第 5 天（价格 = 2）卖出（利润 2），总利润 `3`。

## 提示

- `1 <= prices.length <= 5000`
- `0 <= prices[i] <= 1000`

## 为什么它属于「交易成本维」

```
笔数维（限制交易次数）：121（1 笔） → 188（k 笔） → 123（k = 2 特化）
交易成本维（k 无限制）：122（无限笔） → 309（+ 冷冻期） / 714（+ 手续费）
```

两支的改法方向正好相反，这是本族最值得记的一句话：

| 题 | 限制的本质 | 在 122 上改什么 |
| --- | --- | --- |
| 714 | 多花一笔钱 | 改「**扣多少**」：卖出时 `- fee` |
| 309 | 买入被推迟一天 | 改「**钱从哪来**」：买入的现金只能是「非冷冻空仓」 |

## 核心：状态从 2 个变成 3 个

122 只有两个状态：`hold`（持股）/ `cash`（空仓）。冷冻期让「空仓」分裂成两个时间点不同的状态：

| 状态 | 含义 | 明天能做什么 |
| --- | --- | --- |
| `hold` | 持股 | 只能卖或不操作 |
| `sold` | **今天卖出**（明天冷冻） | 明天不能买 |
| `rest` | 空仓且**不在**冷冻期 | 明天可以买 |

于是转移变成：

```js
hold = Math.max(hold, rest - p)   // 买入的钱只能来自 rest（非冷冻空仓）
sold = prevHold + p               // 今天卖出
rest = Math.max(rest, prevSold)   // 冷冻结束 → 进入可买入的空仓
```

**关键点：`rest` 用的是「上一天的 `sold`」（`prevSold`）。** 今天卖出的钱明天不能用来买，要等到后天——这就是冷冻期在代码里的全部体现。

## 三个必须想清楚的点

**① 为什么必须用 `prevSold` 而不是 `sold`**
如果写成 `rest = Math.max(rest, sold)`，今天卖出的钱今天就被记进了「非冷冻空仓」，明天就能拿来买 → 冷冻期直接失效，答案会退化成 122。
（这正是 188 里「同日卖买净收益为 0」的同类陷阱：**状态更新的时间边界**，是这一族反复出现的考法。）

**② `hold` 只能用 `rest` 的钱来买**
用 `sold`（今天刚卖的钱）就违反冷冻期；用 `cash` 那种单一空仓变量（122 的写法）根本表达不了「冷冻中」这个时间维度。

**③ 答案取 `max(sold, rest)`**
最后一天可能停在「刚卖出（明天才解冻）」或「空仓等待买入」两处，只取 `cash`/`sold` 会漏解。

## 教学版：三维数组写法（面试先画这张表）

```js
// dp[i][0] 第 i 天持股的最大收益
// dp[i][1] 第 i 天卖出（即第 i+1 天冷冻）
// dp[i][2] 第 i 天空仓且非冷冻
dp[i][0] = Math.max(dp[i-1][0], dp[i-1][2] - prices[i])
dp[i][1] = dp[i-1][0] + prices[i]
dp[i][2] = Math.max(dp[i-1][2], dp[i-1][1])
// 答案：Math.max(dp[n-1][1], dp[n-1][2])
```

三个变量版就是它的滚动数组压缩——面试时**先给三维表说清状态，再压成三个变量**，比直接写三变量得分高。

## 面试追问

| 追问 | 答法 |
| --- | --- |
| 冷冻期改成 k 天怎么办 | 把「空仓」按「距离上次卖出还剩几天冷冻」拆成 k+1 个状态，或用滑动数组维护 k 天前的 `sold` |
| 再加手续费 | 两处可叠加：`sold = prevHold + p - fee`，与 714 组合 |
| 再限制最多 k 笔 | 回到 188 的 `buy[j]/sell[j]`，每个 j 内部再维护 sold/rest 两个空仓态 |
| 为什么不能用差分贪心 | 冷冻期让「连续上升段」不能无限拆开吃（卖一次要停一天），贪心的贪心选择不再稳定 |
