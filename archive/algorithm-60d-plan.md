## 三、训练规则（比题单更重要）

### 3.1 每日节奏（工作日 2–2.5 小时）

```
新题 1 道（40 min，超时看题解，立刻补笔记）
  ↓
二刷 2 道（各 20 min，限时盲写，写完才看历史笔记）
  ↓
手撕 JS 1 道（20 min）
  ↓
复盘 10 min（填四行笔记）
```

周末：60 分钟全真模拟（算法 2 道 + 手撕 1 道，中途不查资料、不跑测试），外加本周错题回炉。

### 3.2 每题必填的五问笔记（沿用你的 DP 文档风格）

文件头加一行复现记录，正文注释写五行：

```js
/**
 * 复现：一刷 09-28 提示 · 二刷 ____ 独立 · 三刷 ____
 * 暴力：____（写清 O(?)，这是面试官唯一想听的开场）
 * 观察到的性质：____（为什么能优化）
 * 否掉：____（第一反应是什么？为什么它不行——复杂度不够还是有反例）
 * 最优：____（状态/模板 + 复杂度）
 * 易错：____（下次要盯的那个点）
 */
```

「否掉」这一行是逻辑图的**边**，缺了它这份笔记就退化成答案抄写。同时把该题的「题干特征 → 候选方向 → 否掉理由」补一行到 [archive/decision-tree.md](decision-tree.md)。

### 3.3 二刷 / 三刷的判定标准

- **一刷**：能看懂 + 能默写 → 只算「学过」，不算「会」。默写验证的是记忆，不是方向判定能力。
- **二刷**（间隔 48 小时）：**限时内独立写对**、且能口述「第一反应是什么 / 为什么不是它」才算通过。写不出来或说不出来 → 回炉重刷，别自欺。
- **三刷**（面试前一周）：只刷「二刷没通过」的和困难题。

### 3.4 用看板脚本跟踪进度（不用肉眼翻文件）

```bash
npm run review              # 全量看板 + 今日建议 3 题
npm run review -- 未开始     # 只看某个状态
npm run review:overdue      # 只看逾期未二刷（一刷后超过 2 天）
```

脚本扫描 `solutions/*.js` 头部的「复现」行，输出 6 种状态：未开始 / 待二刷 / 二刷未过 / 已二刷 / 已三刷 / 缺字段。

- 一刷、二刷填日期即被统计；`二刷 10-02 ✗` 会归入「二刷未过」并优先出现在今日建议里。
- 一刷后超过 2 天仍未二刷 → 标记「逾期 N 天」，并进入今日建议。
- 「缺字段」= 新增解法时忘了写那行，脚本会单独提示。

建议节奏：每天开工先跑一次 `npm run review`，照着「今日建议」开做（不用再想做什么）。

### 3.5 面试口述模板（每天挑 1 题练说，不写只讲）

```
① 复述题意与边界（1 句）
② 暴力解 + 复杂度（1 句，先给能跑的）
③ 优化切入点（1 句，「瓶颈在哪 → 用什么结构消除」）
④ 编码（边写边讲关键行）
⑤ 复杂度复核 + 边界自测（手算 1 个反例）
```

## 六、里程碑与自查

| 时间点 | 标志 |
| --- | --- |
| 第 3 周末 | 图 + 树 + 单调栈/二分 三大骨架完成；**把目录名藏起来，能从裸题干特征推出该用哪个模板**（不是能默写） |
| 第 5 周末 | DP / 回溯 / 贪心 全覆盖，困难题 ≥ 12 道 |
| 第 7 周末 | 总题量 ≥ 150，设计题与手撕齐备，开始投递 |
| 第 8 周末 | 限时盲写达标，进入面试节奏（面试本身也是练习） |

每题收尾自查（沿用 DP 文档的自查精神）：

- [ ] 暴力解能 30 秒内说清并写出？
- [ ] 优化切入点是「消除哪个瓶颈」而不是「我记得这么做」？
- [ ] 能说出至少一个**被否掉的方向**，以及否掉它的理由（复杂度不够，还是有反例）？
- [ ] 复杂度推导（状态数 × 转移代价 / V+E / n log n）能口述？
- [ ] 边界：空、单元素、全相同、极值、溢出，手算过至少 2 个？
- [ ] 二刷记录已填？未通过则标红回炉？

## 七、怎么用这份文件

1. 每周日晚上花 10 分钟：勾掉本周完成项，把未完成的平移到下周（**不要积压超过一周**）。
2. 每完成一个主题，回 `templates/` 补相应模板（待补 09–14 已有清单），并把该族的「题干特征 → 候选方向 → 否掉理由」补进 [archive/decision-tree.md](decision-tree.md)。
3. 面试前 3 天：只看 `templates/` + `handwritten/` + 自己标注的易错行，不再刷新题。
