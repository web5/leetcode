# 模板库 templates/

本目录是「**方向已定之后**」才用的东西：它回答"骨架怎么写"，不回答"该用哪个骨架"。**判断方向的入口是 [decision-tree.md](../decision-tree.md)**（题干特征 → 候选算法）；进来之前先能在脑内走通那一步，再翻这里的代码。面试前把这个推导链走熟，收益高于再刷 50 题。

这里放**与具体题目解耦的骨架代码**，每份都是可直接 `require` 的正确实现，注释里写明「什么时候用 / 为什么这么写 / 易错点 / 复杂度」。

规则：本目录**不参与 jest**（`jest.config.js` 的 `testMatch` 只匹配 `tests/**/*.test.js`）。验证题统一走 `problems/ + solutions/ + tests/` 三件套。

## 怎么用（面试节奏建议）

1. **先在脑内完成方向判定**：看题干的特征词（"连续子数组"/"下一个更大"/"有没有方案数"），在 [decision-tree.md](../decision-tree.md) 对应小节里确认候选方向，并给出**否掉隔壁那个的理由**——说得出理由才算方向定了。
2. **再写骨架，最后填细节**：方向定了之后，在白板/注释里写下模板结构（如「栈存下标、遇大则弹」），再补具体判定——面试官看的就是这个推导过程。
3. **每学一个模板立刻做验证题**，不看模板独立写一遍；写好后再回头对照模板差异。
4. **48 小时内二刷**，并在 `solutions/` 对应文件头补一行 `复现` 字段（写法见 `PLAN.md` §4）。
5. **模板是压缩包，不是答案**：变体题的差别通常只在 ① 判定比较符 ② 结果的收集位置 ③ 边界补偿（如 84 两端补 0）。遇到新题先问「它属于哪个模板 + 差在哪」。
